# 前端功能与体验检查 · 2026-10-23

已完成一轮实际使用检查并落地修复。重点是提交可靠性、批量操作正确性、结果解释与操作反馈。原有本地应用继续使用；部署仍搁置。

检查覆盖结构工作台、预测与导入表单、任务队列、批次管线、序列库、混合云执行、存储缓存、预测管线、研究来源和运行环境。使用桌面浏览器、390px 窄屏、键盘操作、受控慢请求与失败响应。

## 发现与修复

共归纳 13 组问题：高优先级 4 组，中优先级 8 组，低优先级 1 组。全部完成本轮所列修复。优先级表示对这套工作台的操作或结果解释影响。

| # | 级别 / 类型 | 原来的操作问题与复现方式 | 当前行为 |
|---|---|---|---|
| 1 | 高 / 科学结果 | 导入 PDB 的 B=20，附带 pLDDT=95 时，右侧显示高置信度，三维却读取 B 因子着色。 | 使用已对齐残基的 pLDDT，按链、残基编号、插入码匹配原子。缺失、非法或无法唯一匹配时用灰色；真实 0 保留低置信度颜色。 |
| 2 | 高 / 参数正确性 | AF3 填 samples=2、recycles=7，关闭重开或切换引擎后变为默认 5/10。 | 每个引擎保留独立参数草稿；名称、序列和参数在本页内关闭、重开、切换时保留。没有新增敏感序列的持久浏览器存储。 |
| 3 | 高 / 批次正确性 | 先筛“就绪”，请求未返回时改筛“失败”，旧请求会把就绪目标画到失败列表；切换批次时动作也可能作用于未显示的 ID。 | 以批次 ID、阶段、页偏移识别请求，只发布匹配当前选择的数据。切换期间限制操作，错误时不会把旧行冒充当前筛选。 |
| 4 | 高 / 提交正确性 | POST 已接收，但随后的任务列表请求失败，错误写入关闭的弹窗，用户看不到已创建任务，容易重复提交。 | 先记录并展示已接收任务，再刷新列表。刷新失败单独提示“已接收”；用户已转去另一页时保留其导航，成功结果仍进入任务列表。 |
| 5 | 中 / 工作流 | 常驻节点模式将 AF3 等模型一律写成“尚未配置”，表单按钮禁用，却仅建议配置单次运行器。 | 明确显示“从批次管线提交”，在引擎选择旁提供入口，说明序列库、MSA 策略、执行位置的下一步；返回时保留原表单。未自动把复合物草稿拆成独立任务。 |
| 6 | 中 / 输入保护 | 示例请求较慢时，用户先输入新序列，返回的示例覆盖新输入。 | 仅当等待期间输入未改变时载入示例；输入过长的快速批量请求在 POST 前提示使用流式批次入口。 |
| 7 | 中 / 操作反馈 | 连点提交或批次暂停会产生重复请求，取消批次前没有看到具体影响。 | 提交中显示忙态并防重入；批次动作绑定显示的 ID，错误就地保留。取消前展示批次名、未完成数量和保留结果，默认焦点为“保留批次”，支持 Escape。 |
| 8 | 中 / 结果选择 | 连续打开两个任务，较早的详情响应晚到后抢回旧任务。 | 保留最后一次选择；切换到其他页面后不被迟到请求拉回。 |
| 9 | 中 / 连接恢复 | 请求中断后恢复，侧边栏可能仍显示离线；打开的表单也可能保留旧的引擎不可用状态。 | 有持续断线提示和手动重连入口，保留当前内容；恢复时更新连接与引擎状态，同时保留参数。 |
| 10 | 中 / 队列反馈 | 搜索框聚焦时跳过重画，列表后台已更新，之后也不再重画；详情请求失败可进一步吞掉列表更新。 | 只更新表格，保留搜索框、焦点和滚动；先提交已成功读取的列表，再读取选中详情。导出明确为“当前筛选”，内容与当前名称/状态条件一致。 |
| 11 | 中 / 存储翻页 | 缓存计划先改变页偏移，网络失败后页码与内容不一致；快速翻页或离页的迟到请求造成错页、弹窗再出现。 | 页码与数据一起提交，单次加载、防重复，失败保留原页并可重试；关闭或离页后废弃迟到请求。 |
| 12 | 中 / 键盘可用性 | 集群轮询替换按钮，键盘焦点丢失；关闭批次详情难以回到原位置。 | 保留批次按钮、展开项的语义焦点；弹窗有可访问标题，关闭后回到当前页面对应入口。 |
| 13 | 低 / 视觉与导航 | 窄屏导航只剩相近图标；预测表单说明与引擎文字偏小。 | 窄侧栏增加“结构、任务、批次、序列库、混合云…”文字，标记当前页；扩大关键表单文字与焦点轮廓，滚动表单保持操作区可见。 |

## 验证与证据

新增及专项检查共 **38 项**：

- `browser_studio_ux.cjs`：11 项，参数保留、慢示例、提交忙态、批次引导、任务选择乱序、连接恢复、筛选导出、提交后刷新失败、390px 布局。
- `browser_campaign_ux.cjs`：10 项，筛选与批次切换乱序、失败反馈、动作去重与取消确认。
- `browser_operations_ux.cjs`：5 项，存储翻页恢复和集群键盘焦点。
- `browser_workspace_recovery_ux.cjs`：3 项，详情失败不冻结表格、提交后导航保留、重连刷新打开的引擎表单。
- `browser_confidence_color_ux.cjs`：4 项，生产着色函数与 3Dmol API 夹具，包含多链同号、插入码、独立 pLDDT 与 B 因子、缺失和真实 0。
- `browser_workspace_ux_live.cjs`：5 项，对主服务的只读检查，覆盖实际结构显示、9 个导航入口、常驻模式入口、窄屏、记录保护。

已有功能回归 **66 项**：固定靶标流式导入 11、真实 HTTP 目标详情 12、PAE 按需分析 13、MSA 策略 10、存储原场景 12、流式解析客户端 8。JavaScript 语法检查通过。

测试中修正了两个旧夹具接口：可用性函数增加 profile 参数；准备失败注入移到当前 `prepare_cooperative` 入口。修正前失败原因与重跑结果均保留，不以放宽业务断言使测试通过。

除主服务只读浏览外，创建、失败注入、取消确认等使用独立临时账本或模拟 API。主服务 **5 个批次、2 个任务的 ID 完全不变，浏览器没有发出写请求**。本轮没有改后端计算管线、安装依赖、执行部署或作 GPU 性能测量。

## 后续最值得增加的功能（本轮未实现）

1. **批次目标按名称 / target ID 检索**：需要服务端索引和分页查询；在当前 25 行上做本地过滤无法覆盖十万目标，不能冒充全量搜索。
2. **多候选结果比较**：同屏比较序列、pLDDT、pTM/ipTM 与结构，并保留模型来源和配体/链对应关系，减少下载后另开工具的步骤。
3. **可复用提交模板**：保存数据库 profile、MSA 策略、执行位置和模型采样设置；创建新批次时重新做可用性预检，避免复制旧版本配置后无声失效。

这些属于下一轮功能建设；本轮优先消除了会丢参数、显示错目标、误读置信度和重复提交的具体问题。
